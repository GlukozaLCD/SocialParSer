# SocialParSer

Мультиплатформенный сборщик данных соцсетей. Собирает данные по пабликам/каналам в Instagram, TikTok, VK, Telegram и YouTube: ссылки на новые посты за сутки и метрики (просмотры, лайки, комментарии, репосты, сохранения, число подписчиков).

## Статус

Оба функциональных плана из реестра (см. [`PLAN.md`](PLAN.md)) реализованы целиком: ежедневный сбор ссылок по пабликам, и сбор метрик постов + числа подписчиков. Ручной запуск, встроенный планировщик и подключение внешнего (Task Scheduler/cron) — всё работает.

**Что уже работает:**
- `setup.bat`/`setup.sh` — разворачивают окружение, включая браузер Playwright для TikTok (ставится внутрь папки проекта, не в системный кэш).
- Стартовый мастер и меню настроек (`python main.py settings`) — добавление/удаление пабликов, ввод/изменение/отключение учётных данных платформ.
  - Telegram — при вводе api_id/api_hash сразу проводится одноразовый интерактивный вход (код из приложения); повторно не спрашивает, пока сессия не истечёт.
  - Instagram — сначала выбирается режим (свои Business/Creator страницы через Graph API, либо чужие публичные страницы через вход в отдельный аккаунт); для второго варианта открывается видимое окно уже установленного браузера — вход (включая любую проверку) пользователь проходит там сам, вручную, пароль нигде не сохраняется.
- `python main.py run-once` — реальный сбор: проходит по всем пабликам из списка, группирует посты по пабликам, пишет `data/output/links_<дата>.json`, затем сразу же — метрики этих постов и число подписчиков по каждому паблику, пишет `data/output/metrics_<дата>.json` (можно отключить `--skip-metrics`/`--skip-subscribers`, по отдельности или вместе). Если у какой-то платформы истёк токен или её ещё не подключили — остальные всё равно собираются, а причина сбоя попадает и в консоль, и в сам файл результата (раздел `errors`). Код выхода всегда `0`, даже при частичном сборе — это фоновая ежедневная задача, а не операция, которая должна падать целиком из-за одной платформы; но сам факт, что что-то не собралось, не теряется — в файле есть поле `status` (`ok`/`partial`), и в `data/logs/parser.log` пишется отдельная предупреждающая строка. Кому нужно на это реагировать — смотрит на `status`/лог, а не на код выхода.
- Логирование в `data/logs/parser.log` + консоль.

## Требования

- Python 3.10+ (проверено на 3.13).
- Windows или Linux — программа проектируется портативной: скопировали папку на другую машину — она работает там же, без правки путей вручную.
- Для мастера и меню настроек нужен обычный интерактивный терминал (окно консоли — cmd.exe, PowerShell, Windows Terminal, обычный Linux-терминал). Если запустить их с перенаправленным выводом или в нестандартной встроенной консоли — будет понятное сообщение об ошибке вместо зависания.
- Около 700 МБ свободного места под браузер Playwright (нужен только для TikTok-адаптера, ставится один раз при `setup.bat`/`setup.sh`).

## Установка

Windows: найдите файл `setup.bat` в папке проекта в Проводнике и запустите его **двойным щелчком**, как обычную программу — это единственный шаг во всей инструкции, который не нужно печатать в терминале. Откроется чёрное окно, в нём какое-то время побегут строчки — это нормально, идёт установка. В конце появится «Готово...» и окно будет ждать нажатия любой клавиши, чтобы закрыться.

Linux/macOS: `setup.sh` запускается из терминала (`bash setup.sh`) — см. следующий раздел, как открыть терминал в папке проекта.

Скрипт создаёт виртуальное окружение `.venv/` и ставит зависимости из `requirements.txt`. Само окружение не переносится вместе с папкой проекта на другую машину — на новом месте его нужно один раз пересоздать этим же скриптом.

## Как вводить остальные команды

Всё, что дальше в этом README выглядит как `python main.py ...` — это не то, что открывается двойным щелчком. Такие строчки нужно **напечатать в окне терминала** и нажать Enter. Если вы никогда так не делали — вот по шагам.

> ℹ️ Команду можно печатать именно так, как она написана в README — `python main.py ...`. Программа сама находит и использует правильный Python внутри `.venv`, даже если в терминале команда `python` указывает на что-то другое; отдельно печатать путь до `.venv` не нужно.

### Открыть терминал в папке проекта (Windows)

1. Откройте Проводник и зайдите в папку проекта (туда, где лежит `main.py`).
2. Зажмите клавишу **Shift** и щёлкните **правой** кнопкой мыши по пустому месту внутри папки (не по файлу).
3. В появившемся меню выберите **«Открыть окно PowerShell здесь»** (на разных версиях Windows может называться «Открыть терминал здесь» / «Open PowerShell window here» / «Открыть в Терминале»).
   - Если такого пункта нет: кликните один раз в адресную строку Проводника (где показан путь к папке), напечатайте `powershell` и нажмите Enter — откроется то же самое.
4. Откроется тёмное окно с текстом и мигающим курсором — это и есть терминал. Он уже «стоит» внутри нужной папки, дополнительно никуда переходить не нужно.

### Ввести команду

Кликните внутрь этого окна, напечатайте нужную строку (или вставьте скопированную — в PowerShell это обычно клик правой кнопкой мыши по окну, либо `Ctrl+Shift+V`) и нажмите **Enter**. Например, чтобы открыть меню настроек, печатаете ровно это:
```
python main.py settings
```
и жмёте Enter. Через пару секунд появится интерактивное меню — по нему двигаетесь стрелками ↑/↓, выбор — Enter.

### Терминал можно не закрывать

Одно и то же окно терминала подходит для всех команд подряд — выполнили одну, увидели результат, печатаете следующую и снова Enter. Закрывать и открывать заново нужно, только если само окно закрылось (например, после `run-daemon`, который работает, пока его не остановишь через `Ctrl+C`).

### Linux/macOS

Файловый менеджер обычно даёт пункт «Открыть терминал здесь» по правому клику на папке; либо откройте терминал как обычно и перейдите в папку командой `cd`, подставив свой путь:
```
cd /путь/до/SocialParSer
```
Дальше команды те же, что и в остальном README.

## Первый запуск — пошагово

Запускаете `python main.py` в первый раз — программа видит, что `config/credentials.json` ещё нет, и сама запускает мастер настройки. Все введённые данные сохраняются внутри папки проекта (`config/`), в файлы, которые не попадают в git.

### Шаг 1. Выбор платформ

Стрелками/пробелом отмечаете, какие из пяти платформ подключаете (можно не все сразу — недостающие добавите позже через меню настроек, см. ниже). Дальше мастер по очереди спросит учётные данные только для отмеченных.

### Шаг 2. Учётные данные — где что взять

Для каждой платформы — свой набор действий на стороне платформы, программа сама ничего не выпускает.

**VK — access-токен с правом `wall`.** Самый простой способ для чтения открытых пабликов:
1. Зайдите на `vk.com/apps?act=manage`, создайте Standalone-приложение (любое название) — получите его `app_id`.
2. Откройте в браузере (подставив свой `app_id`):
   `https://oauth.vk.com/authorize?client_id=ВАШ_APP_ID&display=page&redirect_uri=https://oauth.vk.com/blank.html&scope=wall,offline&response_type=token&v=5.199`
3. Разрешите доступ — VK перекинет на пустую страницу, в адресной строке после `access_token=` и до `&` будет сам токен. Его и вводите в программу.

**Telegram — API ID + API HASH.**
1. `my.telegram.org` → войти по номеру телефона → «API development tools».
2. Заполнить название приложения (любое) → «Create application».
3. Скопировать `api_id` (число) и `api_hash` (строка).

После ввода этих двух полей программа сама подключится к Telegram и один раз спросит код из приложения (или пароль 2FA, если он включён) — это разовая процедура, сессия сохранится в `config/sessions/`.

**YouTube — API key.**
1. `console.cloud.google.com` → создать проект (или выбрать существующий).
2. «APIs & Services» → «Library» → найти «YouTube Data API v3» → «Enable».
3. «APIs & Services» → «Credentials» → «Create Credentials» → «API key» → скопировать ключ.

**Instagram — сначала выбор режима.**
- *Свои Business/Creator страницы (Graph API)* — сложнее всего технически, через `developers.facebook.com`:
  1. Создать приложение (тип Business) на `developers.facebook.com/apps`.
  2. Подключить к нему продукт «Instagram Graph API» и Facebook-страницу, привязанную к вашему Instagram-аккаунту.
  3. Через «Graph API Explorer» (`developers.facebook.com/tools/explorer`) получить токен с правами `instagram_basic`, `pages_show_list`, и (для метрик) `instagram_manage_insights`.
  4. Там же узнать ID бизнес-аккаунта: запрос `/me/accounts`, затем `/{page-id}?fields=instagram_business_account` — нужное число и есть ID для добавления паблика.
  Экраны Meta меняются со временем — если что-то не совпадает, ориентируйтесь на официальную документацию Graph API, логика (приложение → страница → токен с нужными правами) остаётся той же.
- *Чужие публичные страницы (вход в отдельный аккаунт)* — проще: заведите отдельный Instagram-аккаунт (не основной личный — есть риск блокировки при частых проверках). Вход в него проходит не через имитацию мобильного приложения, а через настоящий браузер:
  1. Программа откроет **видимое** окно уже установленного браузера (того же Chromium, что использует TikTok) на странице входа Instagram.
  2. Введите логин и пароль в этом окне сами, как обычно, и, если Instagram что-то попросит подтвердить (код на почту/SMS, любую другую проверку) — тоже пройдите это прямо там, в браузере, своими руками.
  3. Программа сама, автоматически, увидит, что вход завершён, заберёт из браузера только техническую сессию (без пароля) и сохранит её — окно можно будет закрыть.

  Пароль от аккаунта нигде не сохраняется — вводится один раз прямо в браузер. На это отведено 10 минут; если не успели или окно закрыли раньше времени — просто повторите подключение в `python main.py settings`. Эта конкретная платформа при неудаче просто пропускается — остальные уже введённые данные (VK, Telegram и т.д.) не теряются.

  Важно: этот конкретный шаг настройки (сам вход) должен выполняться на машине с монитором — открывается настоящее окно браузера. Дальнейшая работа программы (`run-once`/`run-daemon`) в браузере не нуждается и прекрасно работает на headless-сервере — это ограничение касается только момента подключения аккаунта.

**TikTok — `ms_token`.**
1. Открыть `tiktok.com` в обычном браузере, войти в свой аккаунт.
2. Открыть DevTools (F12) → вкладка Application (Chrome)/Storage (Firefox) → Cookies → `https://www.tiktok.com`.
3. Найти cookie с именем `msToken`, скопировать его значение.

Эта cookie периодически обновляется/истекает — если TikTok-адаптер начнёт падать с ошибкой авторизации, зайдите в `python main.py settings` и вставьте свежее значение.

### Шаг 3. Добавление паблика — что писать в поле «ID/handle»

| Платформа | Что вводить | Пример |
|---|---|---|
| VK | короткое имя из ссылки или числовой ID группы | `durov` (из `vk.com/durov`) |
| Telegram | юзернейм канала без `@` | `telegram` (из `t.me/telegram`) |
| YouTube | ID канала (с `UC...`) либо `@handle` | `UC-lHJZR3Gqxm24_Vd_AJ5Yw` или `@PewDiePie` |
| Instagram (graph_api) | числовой ID бизнес-аккаунта, полученный на шаге 2 | `17841400000000000` |
| Instagram (scrape) | юзернейм страницы без `@` | `instagram` |
| TikTok | юзернейм профиля без `@` | `tiktok` |

После добавления хотя бы одного паблика мастер спросит «добавить ещё?» — можно сразу занести весь список или продолжить позже через меню настроек.

### Готово

Мастер сохранит всё в `config/` и покажет предупреждение, что `credentials.json` — личный файл (токены/сессии), беречь при передаче папки другим. Дальше можно сразу запускать `python main.py run-once` или продолжить в `python main.py settings`.

## Повторный запуск и дальнейшая настройка

Как только `config/credentials.json` существует, мастер больше не запускается — `python main.py` без аргументов просто печатает список команд. Всё управление — через `python main.py settings`:

- **Добавить платформу, которую пропустили при первом запуске** — «Учётные данные» → выбрать платформу (она отмечена «не подключена») → ввести данные, как в шаге 2 выше. Остальные платформы трогать не нужно.
- **Изменить токен/сессию** — «Учётные данные» → уже подключённая платформа → «Изменить».
- **Сбросить сессию/устройство (Telegram, Instagram)** — «Учётные данные» → платформа (подключена или нет — пункт доступен в обоих случаях) → «Сбросить сессию/устройство». Логин/пароль или api_id/api_hash из `credentials.json` при этом не трогаются — удаляется только файл в `config/sessions/`, из-за которого при следующем входе Telethon/instagrapi заведут сессию/«устройство» заново, с нуля. Для Instagram это же действие удаляет и сохранённый профиль браузера (куки), которым пользовался шаг входа, — следующее подключение откроет полностью чистый браузер.

  Зачем это может понадобиться: Telegram и Instagram, в отличие от VK/YouTube/TikTok, привязывают не только пароль, но и сохранённый «отпечаток» сессии/устройства. Если вход стабильно не проходит (например, Instagram раз за разом требует «Manual verification» / подтверждение через приложение) — возможно, дело именно в этом сохранённом отпечатке, а не в пароле. Сброс — способ начать с чистого листа, не трогая сами учётные данные. Гарантии, что это решит проблему входа, нет (Instagram может блокировать по другим причинам — IP, возраст аккаунта и т.п.), но это первое, что стоит попробовать при повторяющихся ошибках входа.
- **Отключить платформу** — там же → «Отключить» (её паблики останутся в списке, но будут падать с понятной ошибкой при сборе, пока не переподключите).
- **Добавить/удалить паблик** — «Паблики». Править существующий паблик отдельного пункта нет — проще удалить и добавить заново с нужными значениями.
- **Проверить, всё ли готово перед запуском** — «Проверить готовность к запуску»: покажет, каким платформам из списка пабликов не хватает учётных данных, если такие есть.

## Обычное использование

| Команда | Что делает |
|---|---|
| `python main.py settings` | Меню настроек: добавить/изменить/удалить паблик или учётные данные, а также «Проверить готовность к запуску» — покажет, каким платформам из списка пабликов не хватает учётных данных |
| `python main.py run-once [--skip-metrics] [--skip-subscribers]` | Ссылки + метрики постов + подписчики за один проход — вручную или из внешнего планировщика (Task Scheduler/cron). Флаги отключают часть работы для конкретного запуска |
| `python main.py run-daemon [--at ЧЧ:ММ]` | Встроенный планировщик: ждёт указанное время суток (по умолчанию `09:00`, локальное время) и запускает тот же полный сбор раз в сутки. Если это время сегодня уже прошло — дособерёт сразу, не дожидаясь завтра. Остановка — `Ctrl+C` |
| `python main.py collect-metrics [--date ГГГГ-ММ-ДД]` | Вспомогательная команда: пересчитать метрики/подписчиков по уже собранным ссылкам (за сегодня или прошлую дату), не гоняя сбор ссылок заново. Нужен уже существующий `links_<дата>.json` за эту дату |

## Результат работы

Результат каждого прохода — файл `data/output/links_<дата>.json` (за один календарный день файл один, повторный запуск в тот же день перезаписывает). Ссылки на посты за последние 24 часа, сгруппированные по пабликам в том порядке, в котором паблики идут в списке; посты внутри паблика — от новых к старым:

```json
{
  "generated_at": "2026-08-27T09:00:00+00:00",
  "window_hours": 24,
  "status": "ok",
  "publics": [
    {
      "platform": "vk",
      "public_id": "somepublic",
      "public_name": "Название паблика",
      "posts": [
        {"post_id": "-1_2", "post_url": "https://vk.com/wall-1_2", "published_at": "2026-08-27T08:30:00+00:00"}
      ]
    }
  ],
  "errors": [
    {"platform": "telegram", "public_id": "somechannel", "message": "..."}
  ]
}
```

`post_id` — внутренний идентификатор поста для этой платформы (не всегда совпадает с тем, что видно в ссылке) — используется вторым функциональным планом, «сбор метрик постов», чтобы повторно найти этот же пост через API. `status` — `ok`, если собралось всё, `partial`, если хотя бы один паблик не отдал данные (см. `errors` — какие именно и почему: истёкший токен, сетевая ошибка и т.п.). Это не код ошибки — `run-once` в любом случае завершается с кодом `0`, `status`/`errors` нужны тем, кому важно узнать о частичном сборе, не завязываясь на код выхода. Файл можно открыть в любом текстовом редакторе. Передача результата другому боту/сервису по сети пока не реализована — сначала на связь выходит именно этот файл.

Сразу вслед за ним (тем же `run-once`, если не отключено флагами) пишется `data/output/metrics_<дата>.json` — метрики этих же постов и число подписчиков по каждому паблику:

```json
{
  "generated_at": "2026-08-27T09:00:05+00:00",
  "for_date": "2026-08-27",
  "status": "ok",
  "post_metrics": [
    {
      "platform": "vk", "post_id": "-1_2", "post_url": "https://vk.com/wall-1_2",
      "views": 1200, "likes": 34, "comments": 5, "reposts": 2, "saves": null
    }
  ],
  "subscriber_counts": [
    {"platform": "vk", "public_id": "somepublic", "public_name": "Название паблика", "subscribers": 15400}
  ],
  "errors": []
}
```

`null` в метриках — не «посмотрели и там ноль», а «эта платформа так не умеет» (например, «сохранения» есть в API только у Instagram и TikTok — у остальных всегда `null`). Тот же смысл `status`/`errors`, что и в `links_<дата>.json`.

**Передача результата другому боту по сети не реализована.** Программа сознательно останавливается на записи файла — на момент разработки не было известно, кто и как будет принимать данные дальше. Если это понадобится, настраивать доставку нужно на месте: например, дописать в конце `src/cli.py` (после `run_collection()`/`collect_metrics()`) отправку уже готовых файлов `data/output/links_<дата>.json` / `metrics_<дата>.json` (HTTP POST, запись в очередь и т.п.), либо повесить отдельный внешний скрипт, который следит за папкой `data/output/` и передаёт новые файлы дальше. Готового кода под это в проекте нет.

## Автоматический запуск по расписанию

Два равноправных варианта — `run-daemon` (см. выше) для машин без внешнего планировщика, либо штатный планировщик ОС, если он уже есть. Пути ниже — подставьте свои; указывать их можно как есть, абсолютными: программа сама находит `config`/`data` по расположению `main.py`, а не по текущей рабочей директории, поэтому `cd` перед запуском не нужен.

**Windows — Task Scheduler** (из PowerShell/cmd, один раз):
```
schtasks /create /tn "SocialParSer daily collection" /sc daily /st 09:00 /tr "\"C:\path\to\SocialParSer\.venv\Scripts\python.exe\" \"C:\path\to\SocialParSer\main.py\" run-once"
```
Удалить задачу: `schtasks /delete /tn "SocialParSer daily collection" /f`.

**Linux/сервер — cron** (`crontab -e`):
```
0 9 * * * /path/to/SocialParSer/.venv/bin/python /path/to/SocialParSer/main.py run-once
```

Это единственная часть системы, которая не переезжает автоматически вместе с папкой проекта — при переносе на новую машину задачу в планировщике ОС (или процесс `run-daemon`) нужно завести заново.

## Тесты

```
python -m unittest discover -s tests -t .
```

Тесты работают на заготовленных данных, без реальной сети и без реальных токенов — проверяют разбор ответов платформ, фильтрацию по дате, группировку по пабликам и запись файла результата. Живой прогон с настоящими аккаунтами тесты не заменяют — это можно проверить только вручную, вписав свои учётные данные через `python main.py settings` и запустив `python main.py run-once`.

## Портативность

Вся программа рассчитана на то, что папку проекта можно целиком скопировать на другую машину и она продолжит работать: все пути в коде — относительные от корня проекта, все данные (конфиги, сессии, логи, результаты) — внутри самой папки, ничего не пишется в системные директории ОС.

## Подробные логи для отладки

Помимо обычного `data/logs/parser.log` (уровень INFO — по нему уже видно, что вообще происходило), есть `data/debug_logs/debug.log` — туда пишется гораздо больше технических деталей: полные ответы API платформ, внутренняя механика библиотек (instagrapi, urllib3 и т.п.). Он всегда ведётся в фоне, отдельно ничего включать не нужно.

Это нужно, когда обычного сообщения об ошибке недостаточно для разбора — например, чтобы понять, что именно ответил Instagram при отказе во входе. Файл наполняется постоянно и сам себя ограничивает по размеру (до ~8 МБ, старое обрезается).

**Именно из-за этой подробности в нём может засветиться то, что не хочется передавать другому человеку** — реальные логины отслеживаемых или подключаемых аккаунтов, IP-адреса, отпечатки устройств, а иногда и сами токены/куки в теле запросов. Поэтому вся папка `data/debug_logs/` — в списке на удаление перед передачей ниже.

## Перед тем как передать программу другому человеку

Просто скопировать папку проекта недостаточно — часть содержимого касается лично вас и не предназначена для чужих глаз. Удалите перед передачей:

| Что удалить | Почему |
|---|---|
| `.venv/` | Локальное окружение, пересоздаётся `setup.bat`/`setup.sh` на новом месте — тащить незачем (тем более там абсолютные пути этой машины). |
| `.playwright-browsers/` | То же самое — браузер для TikTok и для входа в Instagram, пересоздаётся установкой. |
| `config/credentials.json` | Ваши токены/пароли/API-ключи от всех подключённых платформ. |
| `config/watchlist.json` | Ваш список отслеживаемых пабликов — можно оставить, если это не секрет, но по умолчанию тоже личные данные. |
| `config/sessions/` | Сохранённые сессии Telegram/Instagram (включая профиль браузера с куки Instagram) — по сути, чужой доступ к вашим авторизованным устройствам. |
| `data/logs/parser.log` | Обычный лог — менее детальный, но там тоже попадаются реальные имена аккаунтов и адреса запросов. |
| `data/debug_logs/` | Самый подробный и потому самый чувствительный — см. раздел выше. |
| `data/output/` | Результаты сборов — раскрывают, за какими именно страницами вы следите. Решайте сами, критично ли это для вас. |

Всё остальное (`src/`, `tests/`, `main.py`, `README.md`, `PLAN.md`, `requirements.txt`, `setup.bat`/`setup.sh`, `.gitignore`) — можно передавать как есть, там ничего личного.
